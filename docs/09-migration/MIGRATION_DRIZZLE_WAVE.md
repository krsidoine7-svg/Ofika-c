# 🌊 GUIDE MIGRATION DRIZZLE - WAVE CI

## 📋 Contexte

Ce guide vous accompagne pour migrer votre base de données Supabase avec Drizzle ORM afin d'ajouter les colonnes Wave CI à la table `orders`.

---

## ✅ ÉTAPE 1 : Vérifier la Configuration Drizzle

### 1.1 Fichier drizzle.config.ts

Votre configuration devrait ressembler à ceci :

```typescript
import type { Config } from "drizzle-kit";

export default {
  schema: "./drizzle/schema.ts",
  out: "./drizzle/migrations",
  dialect: "postgresql",
  dbCredentials: {
    url: process.env.DATABASE_URL!,
  },
  verbose: true,
  strict: true,
} satisfies Config;
```

### 1.2 Variable DATABASE_URL

Assurez-vous que votre fichier `.env` contient :

```bash
# URL de connexion Supabase (format PostgreSQL)
DATABASE_URL=postgresql://postgres.[PROJECT_REF]:[PASSWORD]@aws-0-eu-central-1.pooler.supabase.com:5432/postgres
```

**Comment obtenir votre DATABASE_URL depuis Supabase :**

1. Allez sur https://supabase.com/dashboard
2. Sélectionnez votre projet
3. Cliquez sur "Project Settings" → "Database"
4. Copiez la "Connection string" (mode "Session" ou "Transaction")
5. Remplacez `[YOUR-PASSWORD]` par votre vrai mot de passe

## 🚀 ÉTAPE 3 : Générer la Migration

### 3.1 Commande de Génération

Exécutez cette commande pour générer automatiquement le fichier de migration SQL :

```bash
npm run db:generate
```

**Ce que fait cette commande :**
- Compare votre schéma TypeScript avec la base de données actuelle
- Génère un fichier SQL dans `drizzle/migrations/`
- Crée les instructions ALTER TABLE nécessaires

### 3.2 Résultat Attendu

Vous devriez voir un message similaire :

```
✅ Migrations generated!
📁 Generated: drizzle/migrations/0001_add_wave_payment_columns.sql
```

### 3.3 Vérifier le Fichier de Migration

Le fichier généré ressemblera à :

```sql
-- Migration generated by drizzle-kit

ALTER TABLE "orders" 
ADD COLUMN "wave_payment_id" text,
ADD COLUMN "wave_payment_url" text,
```

---

## 📊 ÉTAPE 4 : Appliquer la Migration à Supabase

### 4.1 Option A : Push Direct (Recommandé pour le développement)

```bash
npm run db:push
```

**Ce que fait cette commande :**
- Applique directement les changements à votre base Supabase
- Synchronise le schéma TypeScript avec la base de données
- Idéal pour le développement rapide

**⚠️ Attention :** Cette méthode ne crée pas de fichier de migration historique.

### 4.2 Option B : Migration Manuelle (Recommandé pour la production)

Si vous préférez garder un historique des migrations :

1. **Copier le SQL généré**
```bash
# Ouvrez le fichier de migration généré
code drizzle/migrations/0001_*.sql
```

2. **Aller dans Supabase SQL Editor**
- Ouvrez https://supabase.com/dashboard
- Sélectionnez votre projet
- Cliquez sur "SQL Editor"

3. **Exécuter le SQL**
```sql
-- Copiez-collez le contenu du fichier de migration
ALTER TABLE "orders" 
ADD COLUMN IF NOT EXISTS "wave_payment_id" text,
ADD COLUMN IF NOT EXISTS "wave_payment_url" text,

-- Ajouter des index pour optimiser les recherches
CREATE INDEX IF NOT EXISTS "idx_orders_wave_payment_id" 
ON "orders"("wave_payment_id");


-- Ajouter des commentaires
COMMENT ON COLUMN "orders"."wave_payment_id" IS 'ID unique du paiement Wave CI';
COMMENT ON COLUMN "orders"."wave_payment_url" IS 'URL de paiement Wave CI générée';
```

4. **Cliquer sur "Run"**

Exécutez cette requête dans le SQL Editor :

```sql
SELECT column_name, data_type, is_nullable
FROM information_schema.columns
WHERE table_name = 'orders'
AND column_name LIKE '%payment%'
ORDER BY ordinal_position;
```

## 🧪 ÉTAPE 6 : Tester la Migration

### 6.1 Test d'Insertion

Créez un fichier `test-wave-migration.ts` :

```typescript
import { drizzle } from 'drizzle-orm/postgres-js'
import postgres from 'postgres'
import { orders } from './drizzle/schema'

async function testWaveMigration() {
  // Connexion à la base
  const connectionString = process.env.DATABASE_URL!
  const client = postgres(connectionString)
  const db = drizzle(client)

  try {
    // Test d'insertion avec les nouveaux champs Wave CI
    const testOrder = await db.insert(orders).values({
      userId: 'test-user-id',
      orderNumber: 'TEST-' + Date.now(),
      status: 'pending',
      quantity: 1,
      unitPrice: '14600',
      totalAmount: '14600',
      currency: 'XOF',
      paymentMethod: 'wave',
      paymentStatus: 'pending',
      shippingAddress: {
        name: 'Test User',
        email: 'test@example.com',
        phone: '+225 01 02 03 04',
        address: '123 Rue Test',
        city: 'Abidjan'
      },
      // 🌊 Nouveaux champs Wave CI
      wavePaymentId: 'wave_test_' + Date.now(),
      wavePaymentUrl: 'https://pay.wave.com/m/M_ci_8a/c/ci/?amount=14600'
    }).returning()

    console.log('✅ Test réussi ! Commande créée:', testOrder)
    
    // Récupérer la commande pour vérifier
    const retrieved = await db
      .select()
      .from(orders)
      .where(eq(orders.id, testOrder[0].id))
      .limit(1)

    console.log('✅ Vérification:', {
      wavePaymentId: retrieved[0].wavePaymentId,
      wavePaymentUrl: retrieved[0].wavePaymentUrl
    })

  } catch (error) {
    console.error('❌ Erreur de test:', error)
  } finally {
    await client.end()
  }
}

testWaveMigration()
```

## ⚠️ DÉPANNAGE

### Problème 1 : `DATABASE_URL` non trouvé

**Erreur :**
```
Error: Environment variable DATABASE_URL is not set
```

**Solution :**
```bash
# Vérifiez que votre .env contient DATABASE_URL
cat .env | grep DATABASE_URL

# Si absent, ajoutez-le:
echo "DATABASE_URL=postgresql://..." >> .env
```

### Problème 2 : Permission denied sur Supabase

**Erreur :**
```
permission denied for table orders
```

**Solution :**
Utilisez le Service Role Key au lieu de l'Anon Key :

```bash
# Dans .env
DATABASE_URL=postgresql://postgres.[PROJECT_REF]:[SERVICE_ROLE_PASSWORD]@...
```

### Problème 3 : Migration déjà appliquée

**Erreur :**
```
column "wave_payment_id" already exists
```

**Solution :**
La migration a déjà été appliquée ! Vérifiez avec :

```sql
SELECT column_name FROM information_schema.columns
WHERE table_name = 'orders' AND column_name LIKE 'wave%';
```

### Problème 4 : Drizzle ne détecte pas les changements

**Solution :**
```bash
# 1. Nettoyer le cache
rm -rf node_modules/.cache

# 2. Régénérer
npm run db:generate

# 3. Si toujours pas de changement, forcer avec push
npm run db:push
```
